# 全新机器部署

从零把 CesiumLoader 装到一台安卓机器的完整流程。适用于官方包 `com.feimo.astralparty`；渠道服 / 共存版把包名与缓存路径里的包名换掉即可。

整条链路只有两件事：

1. **载荷**：把 SDK、引导 DLL、模组放到游戏的私有目录；
2. **入口**：往游戏的热更缓存包 `__data` 里写一条引导调用，让游戏启动时加载上面那些 DLL。

第 2 步是唯一需要动游戏文件的动作，其余都是往加载器目录里放文件。

---

## 0. 设备与电脑的前提

**设备**

- Android 11 及以上（Android 15 实测可用）；
- 游戏**至少启动过一次** —— Addressables 缓存 `__data` 只有跑过才会生成；
- 有 adb 或 Shizuku 提权通道（本手册用 adb；脚本用的是 `shell` 用户，与 Shizuku 授予应用的权限同级）。

**电脑**

| 依赖 | 版本 | 用途 |
|---|---|---|
| PowerShell | 7.x（`pwsh`） | 跑 `tools/cesium-inject.ps1` / `tools/cesium-deploy.ps1`。Windows PowerShell 5.1 读带中文的脚本会乱码报语法错 |
| .NET SDK | 8 或更高 | 构建 `CesiumLoader.SDK` 与 `tools/CesiumPatcher` |
| Python | 3.10+，带 `UnityPy` | 拆包 / 回填 UnityFS。`python -m pip install UnityPy` |
| adb | platform-tools | `adb` 在 PATH 上，或设置 `ANDROID_HOME` |
| JDK | 21 | 只有构建安卓 App 时需要，本流程不涉及 |

## 1. 构建载荷

```powershell
# SDK（模组与游戏之间的中间层）
dotnet build ..\modding\msvc\loader\CesiumLoader.SDK\CesiumLoader.SDK.csproj -c Release

# 托管引导（Boot.Load 的宿主，注入进游戏的那条调用最终调它）
dotnet build .\managed\CesiumLoader.Mobile.Bootstrap\CesiumLoader.Mobile.Bootstrap.csproj -c Release
```

把产物收进一个载荷目录，例如 `build\payload`：

```
build\payload\
    CesiumLoader.SDK.dll                  ← 来自 loader\CesiumLoader.SDK\bin\Release\netstandard2.0\
    CesiumLoader.Mobile.Bootstrap.dll    ← 来自 managed\CesiumLoader.Mobile.Bootstrap\bin\Release\
    mods\                                 ← 要装的模组，扁平放 <ModId>.dll + 同名资源目录
```

`mods\` 的布局就一种：**扁平 DLL**，即 `mods\StarCoinShopMod.dll`。同名子目录 `mods\StarCoinShopMod\` 只放该模组的随包资源（皮肤、音频、`<ModId>.json` 清单）。桌面版那种 `mods\<ModId>\<ModId>.dll` 的嵌套布局在安卓不需要。

## 2. 部署载荷

```powershell
.\tools\cesium-deploy.ps1 -Serial 127.0.0.1:5555 -Payload .\build\payload
```

脚本会：

- 建好加载器根目录与 `mods / logs / data / disabled_mods / skins` 子目录；
- 逐个推送根目录文件，**推完比对 sha256**；
- `mods\` 打成一个 tar 传过去再解（40+ 个文件逐个推太慢）。

默认加载器根目录是

```
/sdcard/Android/data/com.feimo.astralparty/files/CesiumLoader
```

要换位置用 `-LoaderRoot`。**换过之后第 3 步的 `-LoaderRoot` 必须一致** —— 注入进游戏的引导 DLL 绝对路径是由它拼出来的。

> 为什么不能直接 `adb push` 到目标目录：游戏私有目录的末级目录是 `2750`，`shell` 只能覆盖里面已存在的文件（`660`），不能新建。所以统一「先推到 `/sdcard/Download`，再 `cat >` 灌进去」。

## 3. 注入入口

```powershell
.\tools\cesium-inject.ps1 -Serial 127.0.0.1:5555 -Apply
```

流程与校验：

1. 在设备上按 `bundleKey` 找 `AssetBundles\<bundleKey>\*\__data`，拉到 `build\inject\device-__data.orig`（**这就是回滚用的备份**）；
2. `bundle_assets.py extract` 解出 19 个热更程序集，取 `AstralParty.Runtime.dll`；
3. `cesium-patcher inject-bootstrap` 写 `<Module>.cctor`：
   `Assembly.Load(引导 DLL 绝对路径) → GetType("CesiumLoader.Mobile.Bootstrap.Boot") → GetMethod("Load") → Invoke`，
   整段包在 `try/catch(Exception)` 里 —— **引导 DLL 缺失或加载失败时只吞掉异常，不会让游戏的类型初始化失败**；
4. `bundle_assets.py replace` 回填，重新解包复核程序集 sha256；
5. `-Apply` 时先 `am force-stop` 游戏（Addressables 会持有 `__data`），再推 + `cat >` 覆盖，最后比对设备上的 sha256。

默认 `bundleKey` 是 `4da1f23c112208b0f8df2a1327b4e4ce`。**游戏热更换包后这个值会变**，需要按新值传 `-BundleKey`。

不想直接改设备可以先出产物看看：

```powershell
.\tools\cesium-inject.ps1 -BundlePath D:\dump\__data            # 离线处理一个包
.\tools\cesium-inject.ps1 -Serial 127.0.0.1:5555               # 抓包并注入，但不回写
```

产物在 `build\inject\__data.patched`，状态（原始/新包的 size + sha256）记在 `build\inject\inject-state.json`。

## 4. 验证

启动游戏，看加载器目录下的日志：

```powershell
adb shell "ls -la /sdcard/Android/data/com.feimo.astralparty/files/CesiumLoader/logs"
adb pull /sdcard/Android/data/com.feimo.astralparty/files/CesiumLoader/logs/activity-mod.log
```

看三件事：

| 看什么 | 正常表现 |
|---|---|
| `bootstrap.log` | 有本次启动的 `Boot.Load` 记录（说明入口进去了） |
| `activity-mod.log` | `主线程泵已启动`、各模组 `初始化完成 (状态: Initialized)` |
| `cesium-loader.log` | 自检 dump 里 `主线程 : 泵运行=True 帧数>0`、`每帧回调` 数量与模组数相当 |

`泵运行` 必须是 `True`：每帧回调（面板注入、HUD 覆层、悬浮窗）全部挂在上面，泵停了就只剩事件类模组在工作。

`mod-errors.log` 里如果出现 `MethodNotFind`，是某个模组引用了 SDK 里没有的成员 —— 换对应的模组构建，或把该成员补进 SDK。

---

## 5. 回滚

```powershell
.\tools\cesium-inject.ps1 -Restore -Serial 127.0.0.1:5555
```

把第 3 步保存的 `build\inject\device-__data.orig` 写回设备并校验。回滚后入口消失，游戏回到原版热更包；加载器目录的文件不用管，没人再调它。

## 6. 常见问题

**找不到 `__data`**

先启动游戏一次，退到标题界面即可。缓存位于

```
/sdcard/Android/data/<包名>/files/com.unity.addressables/AssetBundles/<bundleKey>/<bundleHash>/__data
```

`bundleKey` 与游戏版本绑定，换版本要重新确认。

**注入后游戏起不来**

先 `-Restore` 回滚确认能起。注入段的异常护栏只兜引导调用本身；如果连 `__data` 都不是有效 UnityFS，那是回填环节出了问题，用 `inject-state.json` 里的原始 sha256 核对备份。

**模组在，但界面没变化**

看 `cesium-loader.log` 的 `泵运行`；再看该模组的配置是不是被关掉了（`mods\<ModId>\config.json` 里的 `enabled`；停用模组在 `disabled_mods\<ModId>\config.json`）。旧版集中放在 `configs\<ModId>.json` 的配置自 4.0.0 起不再被读取（引导启动时把该目录整个改名 `configs.bak`）。

**渠道服 / 共存版**

包名换成 `com.feimo.jxpd`（渠道服）或 `com.feimo.astralparty.cesium`（共存版），`-Package` 与缓存路径一起换。

## 附：设备上的目录

```
/sdcard/Android/data/com.feimo.astralparty/files/CesiumLoader/
    CesiumLoader.SDK.dll                    SDK
    CesiumLoader.Mobile.Bootstrap.dll      引导宿主
    CesiumLoader.Mobile.API.dll                    可选：安卓悬浮窗 / 触屏控制模组用
    overlay.png                             可选：悬浮窗图标
    mods\<ModId>.dll                        模组本体（扁平）
    mods\<ModId>\                           该模组的随包资源
    mods\<ModId>\config.json                玩家配置（4.0.0 起唯一位置）
    configs.bak\                            旧版集中配置（4.0.0 起废弃）
    disabled_mods\                          停用的模组（挪到这里）
    enabled.json                            停用状态的互操作索引（可缺省）
    logs\                                   运行日志
    data\<ModId>\                           模组自用的持久化目录
    bootstrap.log                           引导层日志
```

**不要**往 `/sdcard/CesiumLoader` 放东西：游戏没有 `MANAGE_EXTERNAL_STORAGE`，在 Android 11+ 上读写不到那个路径。
